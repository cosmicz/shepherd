#+title: Shepherd — three-minute demonstration
#+date: [2026-10-11 Sun]

Use synthetic pages only. Show the actual result and trace: the deciding tier
can change between runs. This is a demonstration, not a promise that a given
page always follows a particular model path.

* Setup
- Start the runtime and ~node demo/serve.mjs~.
- Open the seven local fixture pages in one browser window. Share that
  window in the companion; keep ~/trace~ visible alongside it.
- Start the local model separately if demonstrating model routing.
- If demonstrating cloud review, configure an OpenRouter key and grant
  consent visibly in the companion. A key alone is not consent.
- Only configure a real family handle if the recipient agrees to the demo.
  Otherwise leave family delivery unavailable and say so.
- Check the actual behavior before recording. The operating-system picker,
  speech voice and Messages permission are separate from automated tests.

* 0:00–0:20: Problem and boundary
“Scammers pressure people to act before they can check. Shepherd watches a
surface you choose and offers a plain-language caution. OCR and the first
model stay local; cloud review is optional and uses an excerpt, not a picture.”

* 0:20–0:45: Ordinary browsing
Show weather and news. Point to the actual outcome and cloud counters.
Do not describe a no-signal result as proof that a page is safe.

* 0:45–1:30: Investment invitation
Open the fictional Mars pre-IPO email. Show the reasons and which tier
actually decided. A local high-risk result can settle this fixture without
cloud review; do not claim a cloud escalation unless the trace shows one.
If a cloud call occurs, show its byte count and consent state.

* 1:30–1:55: Support popup
Open the synthetic virus warning. The infection-plus-call-now rule can settle
a concern locally. Show the recorded timing rather than promising a latency.

* 1:55–2:20: Advice rather than pressure
Show the Medicare guide and consumer-protection article. They discuss scam
language without being demands to comply. Show uncertainty if the result is
inconclusive; never substitute a rehearsed answer.

* 2:20–2:45: Evidence and trade-offs
Show the historical seven-fixture comparison in ~eval/README.org~ and its
limitations. The recorded run used fewer cloud calls for routed analysis,
but its policy paths were not identical and target-row adherence was not
scored. Do not extrapolate one run into daily cost or population accuracy.

* 2:45–3:00: Control
Pause. Show capture stopped and cloud consent revoked. Explain that model
advice is uncertain and a person remains in control.

* Fallbacks
- No cloud key or consent: show local behavior without inventing a verdict.
- Local model unavailable: show that status; the support rule still works.
- Capture unavailable: use the labelled synthetic PNG examples.
- Messages unavailable: say that no family notification was delivered.
