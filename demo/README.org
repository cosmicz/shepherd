Local scam and benign fixture pages, their 2x screenshots, expected outcomes and
the demo script. All people, companies, numbers and sites are fictional except
1-800-MEDICARE, the official Medicare line, used on the benign page. Nothing
here makes a network request: every page carries ~default-src 'none'~ and the
server listens on 127.0.0.1 only.

[[file:fixtures.json][fixtures.json]] is the single source of truth. /Tier-0 rules/ is verified by
~check.mjs~. /Target rows/ name the intended path through the
contract v2 routing table, assuming a valid grant, provider and budget; they
are targets for evaluation, not observations. ~check.mjs~ also checks
the manifest itself: rows exist in the table, the route matches the final row,
scams allow only concern and benign pages never allow it.

* Commands
#+begin_src sh
node demo/serve.mjs              # http://127.0.0.1:8099/ and http://<host>:8099/
node demo/capture.mjs [--port N] # rewrite demo/screenshots/*.png (2560x1600)
node demo/check.mjs              # CSP/no-network grep + Tesseract OCR + runtime rules
node demo/check.mjs --rules PATH # until src/domain/assessment.ts exists in this checkout
#+end_src

~capture.mjs~ uses ~SHEPHERD_CHROME~ or the newest Playwright
~chromium_headless_shell~ in ~~/Library/Caches/ms-playwright~, with a throwaway
profile, background networking off and every non-loopback name resolved to
NOTFOUND. Screenshots frame the page under a simulated address bar showing the
live demo host, because the live demo shares the whole browser window.
~check.mjs~ runs Tesseract with the runtime adapter's arguments
(~stdin stdout -l eng --psm 6~) and the runtime's own ~analyzeText~.

The frame always shows the manifest port (8099), so ~--port~ changes only where
capture listens, not the pixels. Capture fails fast if the port is taken. Each
page renders to a fresh hidden sibling file that must be a new, valid PNG before
it replaces the tracked screenshot, so a silent browser failure cannot leave
stale pixels in place.

* Third-party binaries and secrets
~capture.mjs~ launches Chromium and ~check.mjs~ launches Tesseract, both
installed third-party binaries. Each child gets an allowlisted environment
(Chromium: ~HOME~ set to the throwaway profile, ~TMPDIR~, ~LANG~; Tesseract:
~PATH~, ~LANG~ and ~TESSDATA_PREFIX~ only if set), so provider secrets such as
~OPENROUTER_API_KEY~ never reach them. These commands use synthetic fixtures;
no live screen capture or remote inference is required.

* Hosts
Browsers and curl resolve ~*.localhost~ to loopback, so no hosts-file edit is
needed. A lookalike domain for the support popup (for a future address-bar
rule) would need a manual ~/etc/hosts~ entry; the kit never edits it.

* Known limits
- Tesseract does not read the address bar on the support-popup screenshot (the
  full-page blue background) in the committed fixture; it reads it on the others. Relevant to any
  address-bar lookalike rule.
- Rules outcomes depend on OCR; a Tesseract upgrade can change them, which is
  what ~check.mjs~ is for.
