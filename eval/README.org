#+title: Routing evaluation

~eval/routing-eval.ts~ runs eight synthetic 2x demo screenshots through three
policies on the same Tesseract OCR text: local-only (rules plus Qwen3 through
llama-server), cloud-only (each frame's redacted OCR, bounded to 2 KB before
request wrapping), and the routed decision table. All three policies use the
loopback HTTP server and ~HttpAnalyzer~ boundary in the final run.

#+begin_src sh
llama-server -m /path/to/qwen3-8b-q4_k_m.gguf --host 127.0.0.1 --port 8080 -c 8192 --jinja
npx tsx eval/routing-eval.ts
#+end_src
The default is a cloud dry run, but it still invokes the local model.
A paid live comparison must be deliberately requested:
#+begin_src sh
node --env-file=.env --import tsx eval/routing-eval.ts --live-cloud --cap 40
#+end_src

* Limits and provenance
Eight synthetic frames and one final run do not establish population accuracy,
privacy or production economics. Model outputs, latency and costs vary.
Abstentions are reported separately; an abstention on a scam also counts as a
miss. The receipt's per-day figures extrapolate an unchanged fixture mix at
one analysis every five seconds for eight hours, not measured user activity.

Public copies redact private source commit identifiers and local model paths;
they retain original model/runner/fixture/OCR hashes and all measurements.
These are historical source-run receipts, not claims of inference performed on
the later public squash commit. Publication changes documentation, comments,
test labels and fixture descriptions, so source-file hashes may differ even
where executable behavior and fixture pixels are unchanged. The runner records
per-frame request byte counts and costs, not individual payload hashes.
